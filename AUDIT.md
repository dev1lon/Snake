**Настройка для текущего режима**

В CDP открыть Node → Base Mainnet и скопировать endpoint в `RPC_URL` бэкенда.
Включать gas sponsorship для RPC не требуется. Спонсирование включается и
выключается владельцем в CDP; `CDP_PAYMASTER_URL` задаёт адрес proxy upstream,
а не состояние этой функции. [Инструкция CDP](https://docs.cdp.coinbase.com/data/node/quickstart).

Для БД и backend в одном аккаунте и регионе Render использовать Internal
Database URL в `DATABASE_URL`. Для внутреннего соединения TLS не обязателен;
для внешнего требуется. [Документация Render](https://render.com/docs/postgresql-creating-connecting),
[различия соединений](https://render.com/tutorials/postgres-on-render/connection-strings).

При первом старте обновлённого backend схема добавляет `revive_usage.request_id`
и индекс, расширяет числовые столбцы старой схемы. Данные и `recorded_runs`
сохраняются. Расширение столбцов требует блокировки таблиц; на большой БД время
обновления нужно измерить на копии. Продакшен-настройки этим изменением файлов
не обновляются автоматически, если сервис не управляется данным Blueprint.
